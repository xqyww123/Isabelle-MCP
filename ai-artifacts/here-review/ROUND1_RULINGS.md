# Round-1 judge rulings (for round-2 reviewers)

## [fix-autonomously] correctness-roots-adoption-race: ProjectRootMiddleware sets `_asked` before awaiting, so a concurrent second tool call runs with the un-adopted cwd root

Real, and I reproduced it independently rather than trusting either side: a probe FastMCP server carrying only ProjectRootMiddleware, a roots handler sleeping 0.3 s, and asyncio.gather of two tool calls printed `seen: [('B', '/cwd'), ('A', '/adopted/root')]`. The defender is right that the blast radius is narrow (the only durable consumer is isabelle_launch's `_default_session_dirs(_lsp_client.project_root)` at server.py:480, and both measured clients have cwd == root), so 'major' is overstated — but this is not pedantry: the docstring at server.py:254-258 asserts the ordering as an invariant, the fix is three lines with no steady-state cost, and CLAUDE.md's own criterion ('a shape that makes an invariant impossible to violate beats one that asks people to remember it') applies exactly here. This id and elegance-roots-adoption-race are the same finding; one fix closes both.

**Fix plan:** In ProjectRootMiddleware (src/isabelle_mcp/server.py:260-271) add `self._lock = asyncio.Lock()` in __init__ (safe at import time on Python >= 3.12, pyproject.toml:10, since the lock binds its loop lazily) and use double-checked locking, setting the flag after the adoption completes: `if not self._asked: async with self._lock: if not self._asked: await _adopt_client_roots(context.fastmcp_context); self._asked = True`. The outer unlocked read keeps the steady-state cost at one boolean. Do NOT simply move `self._asked = True` below the await without the lock — that makes every concurrent call issue its own roots/list. Add the regression test described under tests-3.

## [dismissed] correctness-display-position-regex-fabricates-a-path: `_display_position`'s regex claims any position-span text ending in `:<digits>` is an absolute path, and `os.path.realpath` then invents one from the server cwd

The critic concedes there is no producer, and the two 'measured' demonstrations are hand-fed strings, not pipeline output — `' (line 12 of "x"):3'` in particular cannot occur, because position.ML:285-287 emits the separator space OUTSIDE the markup and never appends anything after s2 inside it. I checked the defender's key structural claim myself: make_html's generic branch is `html_class(c, html)` with `c = markup.name` (browser_info.scala:527-543) — markup properties never reach the HTML — so suggested fix (b), 'an extra property on the markup', is not implementable at all. That leaves fix (a), an `os.path.isabs` guard, on which the defenders themselves split: it swaps one cosmetic rewrite for another, and in the one semi-plausible relative case (a relative -d dir) realpath against the server cwd is the very base the prover used, so the guard would make output worse. Zero reachability, contested direction, no consequence beyond one cosmetically wrong string. The invariant it wants documented already is, at formatters.py:127-130.

## [dismissed] correctness-input-and-output-roots-diverge: Displayed paths become root-relative while `isabelle_evaluate_to` and friends still resolve a relative `file_path` against the process cwd

The premise 'two accepted-relative bases' does not hold. I read the contract: docs/SPECIFICATION.md:770 ('positions are 1-indexed and file paths absolute') and docs/archive/DEBUGGER_DESIGN.md:254-256 ('all `file_path` arguments are absolute paths … `isabelle_del_breakpoints` additionally accepts the project-root-relative form its listings print'). So there is exactly one accepted relative base, the project root, implemented by `_normalize_ref_path` (debugger.py:1123-1128, used only at :1146) — and that round trip becomes MORE correct under the change, since `_display_path` (debugger.py:899-900) prints against the same `client.project_root` that `_normalize_ref_path` joins back. `os.path.realpath(file_path)` at the seven entry points is base-independent on the documented absolute input; 'does not reject a relative path' is not 'declares a cwd base'. The asymmetry is a genuine design question, but a spec one — I route it to the user rather than acting on it.

## [dismissed] correctness-roots-list-changed-ignored: `roots/list_changed` is never handled, so a root change mid-session leaves paths relative to a stale root forever

The handler demand is refuted on both consequence and cost. ## [dismissed] elegance-separator-space: The separating space is emitted inside the position markup, contrary to Position.here, and the `(\s*)` regex group exists only to undo that

The convention being invoked does not exist for the branch that is rewritten: position.ML:282 gives `s1 = ""` for the ⌂ case, so Isabelle emits no separator there at all and the resolver's leading space is new, not moved.
